## Release notes - Module Library 9.60

### New Features
---
- Added contact-aware invoice lists with invoice scope selection, refiners, server-side sorting, and paging.
- Added permission-group access controls for B2B contacts in B2B modules.

### Updates
---
- Added recipient selection for account statements and invoice copies. When invoices belong to multiple organizations, only contacts shared by all selected organizations are available.

### Bug Fixes
---
- Fixed account statement recipient selection in Manage Organization Users.
- Fixed renaming and deactivating contact-model users by sending keyed BusinessPartnerUsers update requests.
- Fixed singular labels in B2B account tiles and order template lists when the count is one.
- Fixed the missing "Shared by" name on the initial render of shared order templates.
- Fixed B2B contact and on-behalf-of account details overflowing the header at increased browser zoom.
- Fixed order template audit messages identifying the impersonated customer instead of the signed-in account manager.
- Made the full "Order placed by" value available when order history truncates it.
- Fixed requesting invoice copies for rows appended by "Load more", batching selected invoices, and filtering shared recipients.
- Fixed invoice recipient email selection to follow the selected invoices' organizations and blocked submission when no shared recipient exists.
- Preserved catalog selection when following the header logo or home link.
- Scoped the SimpleProduct application cache key by locale to prevent product names appearing in the wrong language.
- Fixed contact lookup when an on-behalf-of user switches organizations after selecting a contact without user-creation permission.
- Fixed B2B contact field visibility, admin-contact management permissions, and the mobile user-details Cancel button in Manage Organization Users.
- Fixed long "Order placed by" values displacing order details and product images; values now truncate with a tooltip or wrap on mobile.

The Manage Organization Users fixes are enabled by default. Setting `requestContext.features.disable_b2b_manage_users_ui_fixes` to `true` restores the legacy behavior. An absent or `false` value keeps the fixes enabled.
